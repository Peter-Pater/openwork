### 1. High-Level Architecture                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                 
  OpenWork separates the interface from the execution boundary using a Client-Server architecture:                                                                                                                                               
                                                                                                                                                                                                                                                 
    graph TD                                                                                                                                                                                                                                     
        UI[Vite React App / apps/app] <-->|HTTP / SSE / WebSocket| Server[Node Server / apps/server]                                                                                                                                             
        Electron[Electron Shell / apps/desktop] -.->|Spawns / Manages| Server                                                                                                                                                                    
        Server <-->|IPC / Process Spawn| OpenCode[OpenCode CLI Engine]                                                                                                                                                                           
        Server <-->|MCP| Plugins[MCP Server / Plugins e.g. GWorkspace]                                                                                                                                                                           
                                                                                                                                                                                                                                                 
  • The Client (Vite React Frontend): Located in app. It handles rendering the session timelines, executing plan visuals, settings panels, and prompting the user for permissions.                                                    
  • The Desktop Shell (Electron): Located in desktop. It wraps the React app, configures OS integration (like accessibility and menus), handles window bounds, and manages the lifecycle of the local server.                             
  • The Server (Node/TypeScript): Located in server. It is the control interface for managing local files, securely storing credentials in the vault, launching tool execution plugins (MCP), and executing CLI actions.                 
  • The Orchestrator (CLI Host): Located in orchestrator. It packages the Server, the OpenCode Engine, and the multi-workspace routing into a single, headless terminal daemon ( openwork  CLI command).

  ### 2. Why a Client-Server Architecture?                                                                                                                                                                                                       
                                                                                                                                                                                                                                                 
  • Local-First, Cloud-Ready: A separation of the UI from the server means the exact same React interface can interact with a server running locally on your computer (Host Mode) or a remote worker running in the cloud (Client Mode). You     
  simply change the server URL.                                                                                                                                                                                                                  
  • Auditable & Permissioned Workflows: The server acts as a proxy. When an agent attempts a privileged action (like reading calendar events or editing a code file), the server suspends execution, requests user confirmation from the UI      
  Client, and waits for a reply before sending credentials or proceeding.                                                                                                                                                                        
  • Isolation: Keeping CPU-intensive operations (such as file system scanning, AST parsing, and running shell commands) inside separate Node processes prevents the UI thread from locking up or freezing.

  ### 3. Core Technologies                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                 
  • Frontend: React 19, TypeScript, TailwindCSS, TanStack Query (data fetching), Zustand (global state), and shadcn/ui.                                                                                                                          
  • Desktop Wrapper: Electron (driving Chromium for rendering tabs/panels and Chrome DevTools Protocol integrations).                                                                                                                            
  • Backend Server: Node.js, TypeScript, Express, and Server-Sent Events (SSE) to stream agent updates.                                                                                                                                          
  • Storage: AES-256 encrypted local vaults ( oauth.vault ) stored in standard paths (like  ~/.config/openwork/ ).

   Run Command    │ Target Components                             │ Why Use It
  ────────────────┼───────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────

  #### How to Proceed After Running the Orchestrator                                                                                                                                                                                             
                                                                                                                                                                                                                                                 
  When you run the orchestrator (via  pnpm --filter openwork-orchestrator dev -- start --workspace /path/to/workspace ), it starts the background server in headless mode and prints pairing details:                                            
                                                                                                                                                                                                                                                 
  1. Look for the OpenWork Connect URL and Client Token printed to the terminal.                                                                                                                                                                 
  2. To interact with it, open your browser (or standard UI client) and navigate to the printed address (e.g.,  http://127.0.0.1:8787/?token=YOUR_TOKEN ).                                                                                       
  3. You can also connect to it by launching the Desktop App and selecting Connect Remote, pasting the orchestrator server URL.                                                                                                                  
                                                                                                                                                                                                                                                 
  For more details on CLI parameters, refer to README.md.

  ### 5. How to Build and Test                                                                                                                                                                                                                   
                                                                                                                                                                                                                                                 
  #### Building the Project                                                                                                                                                                                                                      
                                                                                                                                                                                                                                                 
  • Full Production Desktop App Bundle:                                                                                                                                                                                                          
    pnpm build                                                                                                                                                                                                                                   
  This executes build.mjs which compiles TypeScript files to JavaScript, stages them inside Electron resources, and invokes  electron-builder  to output a  .dmg  or  .app  bundle.                                                         
  • Static UI Bundle Only:                                                                                                                                                                                                                       
    pnpm build:ui                                                                                                                                                                                                                                
  Compiles the static React assets to  apps/app/dist  for loading via a web server.                                                                                                                                                              
                                                                                                                                                                                                                                                 
  #### Testing the Project                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                 
  Tests are split into health checks, unit tests, and integration tests:                                                                                                                                                                         
                                                                                                                                                                                                                                                 
  • Run All Core E2E Tests:                                                                                                                                                                                                                      
    pnpm test:e2e                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                 
  • Specific Targeted Tests:                                                                                                                                                                                                                     
      • To test workspace file tracking:  pnpm test:fs-engine                                                                                                                                                                                    
      • To test session initialization:  pnpm test:sessions                                                                                                                                                                                      
      • To test permissions checks:  pnpm test:permissions                                                                                                                                                                                       
                                                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                 
  All task script definitions are listed in the root package.json.
